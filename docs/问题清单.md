## 第一批：工程基线修复（提交 `32090d1` ~ `7adb3e5`，Keil 0/0）

### #1 `char*` 传 `uint8_t*` 产生 4 条警告
- **定位**：Keil 编译输出直接指向 `App_Car.c` 的 OLED 显示调用，`OLED_ShowString`
  形参是 `uint8_t*`，实参是字符串字面量（`char*`）。
- **修复**：`17f9962` 把 `OLED_ShowString` 原型改为 `const char*`（显示函数本就不该
  修改字符串，语义上也更对）。
- **回归**：Keil 全量编译 0 Warning。

### #2 `main.c`/`usart.c` GBK 编码，其余文件 UTF-8
- **定位**：编辑器打开乱码 + `file`/十六进制对比换行与字节差异。
- **修复**：`54a20bd` 统一转 UTF-8（无 BOM）。
- **回归**：编辑器全仓无乱码；后续 Keil 中文注释正常。

### #3 卡尔曼 `dt=0.005`，实际采样 10ms
- **现象**：动态工况下滤波"跟不上"，收敛特性与理论不符。
- **定位**：打印 `vTaskDelayUntil` 实参与滤波 `dt` 对比：0.01 vs 0.005，预测步
  `angle += ω·dt` 增益差 2 倍 → 过度信任陀螺。
- **修复**：`7592483` 引入 `Car_Config.h`，`CAR_SAMPLE_PERIOD_S` 单一来源，采样周期
  与 dt 编译期绑定。
- **回归**：SIL E3（台架卡尔曼 RMS 0.091°）+ 单测 28 断言。

### #4 `HAL_ADC_Start` 后未 Poll 就取值
- **定位**：HAL 单次转换模式文档 + 代码走查——`HAL_ADC_GetValue` 在转换完成前
  返回上一次残留/0。
- **修复**：`App_Car_Display` 补 `HAL_ADC_PollForConversion`（`7592483` 期间），
  后重构时移入 `BSP/bsp_adc.c`。
- **回归**：代码走查；显示值合理性需上板确认 ⏳。

### #5 三环叠加后无限幅直接写 CCR
- **现象**：PWM=ARR=7199，三环叠加可远超此值 → 写入比较寄存器的是截断脏值。
- **修复**：`PID_Clamp` 统一限幅（叠加后 + 每环输出 + 积分，三级），
  `Car_Config.h: CAR_PWM_LIMIT` 单一定义。
- **回归**：单测 15 条限幅断言（边界值精确断言）。

### #6 `sprintf` 无边界（`bat_str[5]` 等）
- **修复**：全部改 `snprintf` + 缓冲区按最坏格式化长度核算（8 字节覆盖 `-32768`），
  位置从 `App_Car.c` 移到 `Port/port_display` 实现里。
- **回归**：cppcheck 无溢出告警 + 代码走查。

### #7 临界区内 `vTaskDelete(NULL)`
- **现象**：自删除后仍执行 `taskEXIT_CRITICAL()` 序列——任务栈可能已回收。
  实测能跑，但依赖 FreeRTOS 实现细节。
- **定位**：代码走查（对照 `vTaskDelete` 源码：出队后不再调度该任务）。
- **修复**：`813fa69` 先 `taskEXIT_CRITICAL()` 再自删除，注释写明原委。
- **回归**：编译 + 走查说明（属时序正确性，无实机不声称实测）🔧。

### #8 任务栈 128 word 跑 sprintf+浮点，无水位监测
- **修复（已完成部分）**：`813fa69` 开 `configCHECK_FOR_STACK_OVERFLOW=2` + 溢出
  Hook（记录任务名 → 全局变量供调试器读，关中断停机，不打印）。
- **🔧 已接线**：`uxTaskGetStackHighWaterMark` 已接入 `@ST#` 状态输出；剩余项是上板采集真实水位数据。

### #9/#10 寄存器版缺失（注释掉的 `TIM2->CNT` 残留 + REG 压缩包没下完）
- **现象**：`Int_Encoder.c`/`Int_TB6612.c` 里留有注释掉的寄存器写法（早期寄存器
  实现的痕迹）；手头的寄存器版本压缩包下载不完整。
- **✅ 修复**：没等压缩包，自己写了两路寄存器实现：
  `bsp_imu_reg.c`（软件模拟 I2C 时序）+ `bsp_motor_reg.c`（RCC/TIM 寄存器直配），
  `BSP_USE_REG` 编译开关切换，Keil 双配置各编译一遍 0 警告（寄存器版代码体积还小 2KB）。

### #11 PID 参数散落为全局变量、无结构体、无持久化
- **修复**：`24b0af9` `car_params_t` 单实例 `g_car_params`（默认值宏

- **⏳ 持久化（Flash 存参）留待后续**；并发保护已用"待写槽位 + 临界区"实现（选临界区而非互斥锁的原因见 App_Car.c 注释）。

### #12 遥控 `switch-case` 单字符，协议不可扩展

### #13 控制环与 OLED 同优先级，周期受刷屏影响
- **现象**：三任务全部优先级 3，SPI 全屏刷新期间控制任务只能排队。
- **修复**：`24b0af9` 优先级分层 PID=5 / 采样=4 / 显示=2 + 通知驱动 + 周期 min/max

## 额外发现（不在原始14项内）

### #15 仿真模型参数必须标定，否则"验证"是自欺
- **现象**：SIL 首版电机常数 2.0 m/s² → 控制权威临界角 11.5° < 初始倾角 10°，
  E1 必翻；加大到 5.0 又因能量管理不当振荡发散。
- **定位**：开环隔离测试（固定 PWM 推摆体）+ 闭环细轨迹逐拍比对
  （`u`、`a_act`、θ、ω 对照动力学方程手算）。
- **修复**：以"默认增益在 10° 下收敛"为约束做参数网格搜索，钉死
  `A_FULL=6.5 / TAU=8ms / C_V=4.0`，依据写进 `pendulum_model.h` 头注释。
- **回归**：E1/E2 `--check` 进 CTest。

### #16 MinGW 工具链在中文路径下的编码缺陷
- **现象**：libgcov 写不出非 ASCII 路径的 `.gcda`；本机 ninja 的
  `FindFirstFileExA` 偶发 ERROR_INVALID_NAME。
- **修复**：`Host/run_checks.sh` 自动在 `%TEMP%` 建 NTFS junction，全流水线走
  ASCII 路径——确定性绕过，脚本头部写明原因。

### #17 倾角保护在翻滚时"反复启停"（SIL E6 首版实测）
- **现象**：60° 倒地实验里保护触发后，翻滚过程中 PWM 又间歇性出现
  （几十 Hz 的切-放抖动）。
- **定位**：E6 逐拍轨迹 —— 小车连续翻滚时加速度角经 `atan2` 回绕
  （θ=231° 加速度计只能读出 −129°），卡尔曼被量测拉回，`|倾角−目标角|`
  在 45° 阈值两侧来回穿越；另外两轮车翻滚时陀螺数百 deg/s、融合角与
  真值短时背离，电平式阈值在这种工况下本质不可靠。
- **修复**：锁存式保护 —— 越限即锁定，只有"倾角<10° 且 |陀螺|<30°/s"
  **持续 0.5s**（驻留计数）才解锁。翻滚时陀螺条件永远不满足 → 持续切断；
  扶正放稳半秒自动恢复（预期产品行为）。阈值与驻留时间在 `Car_Config.h`。
- **回归**：SIL E6 `--check` 进 CTest（trip=YES 且 0.5s 后 PWM 恒 0）。
